# 中心参考温漂修正：部署、验收与回退

用于在已有 PA11 自适应床网中新增温漂修正，或维护该模块。算法、坐标与命令语义集中在[专题文档](../../../docs/adaptive-mesh-drift.md)，不把此项扩展成全机重新安装。只整理或发布资料时，不连接机器实施改动。

## D1：核对输入和接口（P1/P2）

1. 读取目标 Klipper 实际服务解释器、床网/probe/homing/stepper_enable 源码及相关 cfg；对照新模块的调用。特别检查 `bed_mesh.bmc`、`orig_config`、`update_config`、`_get_adjusted_points`、`probe_finalize`、`probe.run_probe`、`multi_probe_begin/end`、`get_lift_speed`、`toolhead.manual_move/get_last_move_time` 与实际归位 rail 事件/名称。版本名相同也不能忽略厂商差异。
2. 目标是自动、矩形网格且无 faulty_regions；不满足时先明确适配范围，不绕过代码拒绝。确认现有自适应 bounds resolver 和 ADXL 依赖；独立全床命令不需要 ADXL，但仅选自适应功能仍要独立适配 resolver。
3. 从实际热床范围确定固定参考点，使用探针坐标，再按目标 XY 偏移换算喷嘴位置；检查两者完整安全范围、clearance、Z行程和返回中心的路线。参考机215/215及偏移只是示例。
4. 核对 native probe 的样本数/中位数/速度/回抬/容差、profile 与退出行为。网格沿用 native 参数，追加参考固定三次中位数；不要顺便改电流、探针 offset、PID 或既有首层基准。

完成证据：已知接口差异、目标中心和可达范围、原有调用链、应改的文件；未知项明确待测。

## D2：准备配套差异与备份（P2/P4）

1. 在本地准备新 `adaptive_mesh_drift.py`，在目标 adaptive cfg 的内部 builder 将原扫描命令替换为 `ADAPTIVE_MESH_DRIFT_CALIBRATE`，保持原 bounds/count/algorithm/profile 参数；添加 `[adaptive_mesh_drift]`。不重命名或覆盖原 `BED_MESH_CALIBRATE`/G29。
2. 保持默认180秒近床等待、每5点追加参考；300秒热床稳定仍属于原 PREPARE 阶段。核对会话有效期和整个准备耗时，时间不足先分析流程，不能静默绕过 AFTER_WIPE 或其一次性授权。
3. 保存将修改的 cfg、已有同名模块（若存在）、所有者/权限/哈希与私有下载副本。记录模块以前不存在时的回退方式；备份不要留在自动 include 通配路径内。
4. 用目标解释器做无硬件动作的语法/接口检查，运行本仓库 `tests/test_adaptive_mesh_drift.py`；它使用测试 fixture 的旧版 native 床网，不能作为未知目标版本的接口验证。目标接口不同则在隔离环境补测实际 finalization，不要求为发布资料在运行机器上重复探测。

完成证据：逐文件差异、可读取备份、旧/新命令清单、离线检查结果及目标接口比较。

## D3：加载与无运动检查（P4）

1. 机器空闲且授权覆盖部署时，安装新模块、合并 cfg。确认实际 include 加载 section；避免有第二份相同 section 或旧宏重定义。
2. 新模块此前未导入时，确认重载后命令、section 和状态对象均存在。改动已导入 Python 时按实际服务重启进程，不能只靠 G-code RESTART 判断代码更新。每次重启后真实归位证据失效。
3. 用 `ADAPTIVE_MESH_DRIFT_STATUS` 检查 interval5、condition180、目标参考点及 running=false；用原 PLAN_ONLY 检查小模型/大模型/PA范围，没有等待或运动。
4. 刚加载时 `real_homed_axes` 应为空；不通过伪造坐标进行实体测试。Ready 不等于可安全移动。

完成证据：Ready、命令/配置正确、计划范围不变，新扫描未自动加热或运动。

## D4：小网格实际验收（P5/P6）

1. 在既有授权及现场条件下确认空闲、钢板装好、无模型、用户在旁和可安全归位。先完成本次启动真实 XYZ G28；需要双Z时沿现有顺序调整并重归Z。不能先从猜测坐标移动到中心。
2. 设置本次验证的温度和固定风扇状态，使用目标机已接受的热稳定流程。参考集成测试为床60°C/喷嘴140°C/主辅风扇关闭；新命令自身不管理温度。验证期间不额外执行 ADXL 接触、擦嘴或挤出。
3. 选可达的小自适应区域，用 PLAN_ONLY 取得实际点数；采用独立临时 profile，在清楚记录原 offset、活动 mesh 和温度/风扇状态后运行扫描。最好包含不足五点的末组，参考机4×4例在第5/10/15/16点后补测。
4. 长请求单独提交，通过状态查询观察180秒conditioning及 mesh/reference 进度。超时先确认后端是否仍运行，不重发实体扫描。
5. 从 last_run 核对 valid=true、原网格N点、追加参考ceil(N/5)、初始参考after_point=0、末组参考after_point=N；每个样本时间应被该组两个参考包围。按公式独立重算修正值，并按 native 扫描排序/offset/profile规则比对实际 probed_matrix。参考点不应多出一行/一列或扩展网格范围。
6. 测试结束先确认能安全移动，再恢复约定的安全高度、测试前 offset/profile、加热/风扇状态；删除临时 profile，不自动 SAVE_CONFIG。失败或坐标状态不明时不发猜测的恢复移动。记录是否成功恢复。

完成证据：实机原始点、时间、参考、修正点、实际矩阵和结束状态；不能只凭一次完成提示宣称精度改善。

## D5：打印链验收与失败处理（P7/P8）

原 Bambu 开始代码中的 `ADAPTIVE_BED_MESH` 已接入新扫描，不再重复插入全床或参考测量命令。确认顺序仍为热稳定/真实归位与所选双Z → 擦嘴 → 清临时offset → 新床网（含近床保持/参考插值）→ 同文件同床温的正式ADXL → 本机首层微调。只有选中 ADXL/擦嘴时才保留对应步骤。

在既有功能验收后验证目标机自己的完整准备和首层；小网格矩阵通过不是整个打印链或第二台机器的完成证据。注意额外测量会增加时间，ADXL会话过期先查范围、时长和第一个错误，不能伪造会话。

参考超限、异常时间、probe通信或native矩阵失败：本次 last_run.valid=false、活动网格清除，停止依赖它的后续打印。先保存状态，查参考可达性、探针、床面/机械状态、真实归位和温度/风扇变化；不删除大偏差点、不反复放宽保护、不凭HTTP超时重复扫描。模块不改全局Z offset。

回退只恢复本批次：比较当前文件是否有用户后续修改，恢复原 builder 调用和此前 cfg；移除本次新增 section，原配置不再加载模块。模块以前存在时恢复其备份，原本没有时可以暂留未加载文件或按记录移除。按实际服务重新加载，检查原命令与Ready，再按重启后真实归位规则验证。不要顺带恢复不相干的旧 printer.cfg、Linux MCU 或整棵 Klipper。

交付记录包含已部署版本、哈希、中心/偏移、参数、验证数据、备份映射和未做的首层/跨机器验证；公共副本不包含实际IP、私有状态日志或备份。
