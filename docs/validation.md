## 上电与重启后的归位规则

**每次上电或重启 Klipper 后，先真实 Home，再做后续 XYZ 移动或床网校准。** 本机原厂配置中已读到延迟宏 `KINEMATIC_POSITION`：启动约3秒后通过 `SET_KINEMATIC_POSITION` 写入 X110、Y110、Z0。这是坐标赋值，没有让电机找到实际原点；工具头真实位置可以完全不同。触摸屏是否也参与该行为尚未单独确认，因此不把原因只归到触摸屏。

给用户的提醒：**上电后未真实归位时，不要随意操作工具头移动，也不要点击网页端“校准床网补偿”按钮**，包括直接启动 `BED_MESH_CALIBRATE`。屏幕或网页上的默认坐标、Ready及“已归零”提示不能代替真实归位。

智能体每次执行 `RESTART`、`FIRMWARE_RESTART`、重启 Klipper 服务或发现重新上电，都必须重新确认归位。确认机器空闲、人在机器旁、归位路径和抬升余量无障碍、接线及探针具备安全归位条件后，在任务授权范围内执行真实三轴 `G28` 并检查成功结果，再进行常规 `G0/G1`、分轴运动测试、擦嘴、Z倾斜调整或床网校准。只查 `toolhead.homed_axes` 不满足要求；不能用 `SET_KINEMATIC_POSITION` 或强制移动绕过。

归位本身会移动，不能在新增驱动方向、探针或空间条件未确认时盲目执行。无法安全归位或归位失败时，先让用户处理接线、机械及空间条件，停止后续移动；不要依据默认坐标先把工具头“挪开”。本次启动内已有真实归位成功证据且位置仍有效时可连续移动，无需每条移动指令前重复G28；再次重启则重新确认。只读检查或不产生XYZ运动的风扇使能检查不要求先进行实体归位。

## 复刻时的验证次序

这里列出简要验证次序。智能体从[复刻总流程](../skills/neptune4max-mods/references/replication-workflow.md)进入，按部署和校准指南逐阶段完成前置检查、操作、证据与失败处理；所选功能的依赖不齐时不能直接跳到完整开始代码。

1. 读取软件基线、解释器、服务和当前配置，备份将变更的文件、Linux MCU程序及权限；把备份下载到电脑。未知厂商修改先比较，再生成差异。
2. 完成断电接线检查，先做不产生XYZ运动的UART检查，并核对安全归位条件。新增驱动方向或探针尚无法确认时，先让用户检查，不盲目移动或归位。
3. 在机器空闲、人在机器旁且路径/间隙已确认时完成真实三轴G28，确认PA11触发和成功归位；遵守上面的重启后归位规则。随后才小幅低速分别验证侧别和正向抬升，恢复横梁姿态后再进行完整双Z调整。观察不清不能靠猜测填写z_positions。
4. 按所选功能验证风扇独立通道、网格可达范围和计划。驱动风扇可在不转动电机的短暂使能测试中验证启动，再恢复原使能状态验证延时；不要为了测试停止而释放正在保持横梁的Z电机。自适应床网PLAN_ONLY可验证算法范围，不代替机械可达性。
5. 有ADXL时核对定制Linux MCU协议，再做高位无接触检查、受控接触重复性、接触窗口和首层。没有支架时不执行硅胶条接触路径。不得把降低阈值、扩大窗口或降低Z下限当成通用消错方法。
6. 运行自己适配的完整切片开始流程和首层测试，记录功能、参数、版本和结果；保留尚未验收项。冷拔、提示音、材料配方作为独立可选维护功能验证。

长耗时G-code请求返回nginx504时，后端可能仍执行。先查询当前状态/命令进度，不自动重发归零、加热、挤出或接触命令。

## 出错时

- UART报错：回到供电、模块/跳线、引脚和地址核对，不先改变机械坐标。
- Z_TILT越调越歪：停止，检查实际侧别、z_positions顺序与方向，不通过放宽容差掩盖。
- ADXL无触发/高位误触发：停止接触流程，检查对应raw轴、传感器、LinuxMCU命令、配方和机械响应。通信/恢复错误禁止盲目重复下探。
- 首层偏差：检查PA11基准、测量点床网补偿、已存在offset和自己的材料首层修正，不能照抄+0.140。
- `RESPOND`格式错误：旧扩展命令解析器会在引号内的分号截断，提示文字用and等替代`;`。仓库冷拔宏已采用修复文本。
- 网页层数异常：检查文件元数据、实际UI算法与变层高/Z-hop，不能默认需要升级整个Klipper。

## 回退

先确认机器空闲并知道哪些文件已改。恢复配套的原Linux MCU程序、对应主机模块和配置，按实际服务关系重新启动；恢复之前比较当前文件是否已被用户后续修改，避免覆盖新设置。保留证据和失败日志的脱敏副本。

运行 `python -B -m unittest discover -s tests -v` 在开发电脑上做离线检查，不连接打印机。Python3的回归通过不证明Python2部署成功，应以目标解释器再做不执行硬件动作的兼容检查。
