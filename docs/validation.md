# 验收、问题定位与回退

## 已有证据

机主已长期使用原机改装，确认当前工作正常。历史记录包含双Z侧别与方向测试、主/辅助风扇测试、提示音试听、ADXL接触重复性及首层使用。MKS驱动替换后，参考配置按R110设0.110Ω，UART寄存器读取成功。这里未把历史单机使用包装成原装批量兼容验证。

本次离线回归验证坐标/床网补偿、热稳定计时、一次性会话、边界解析、接触整组重试及失败恢复。测试中的故障路径是模拟对象，不是本次再次撞床或强制通信断开的实机实验。历史切片测试使用专门归档fixture，与此次用户提供的最新首尾文件分开。

独立的 Python2 autotune 补丁此前在上游固定基线副本应用后，与改装机源码哈希一致。Linux MCU 此次整理了实际需要的定制C，不重新构建或部署。未在第二台原装4Max完成整套适配、接触及打印验收。

## 复刻时的验证次序

1. 读取软件基线、解释器、服务和当前配置，备份将变更的文件、Linux MCU程序及权限；把备份下载到电脑。未知厂商修改先比较，再生成差异。
2. 完成断电接线检查。空闲、人在机器旁、喷嘴有足够间隙时，先检查UART，再小幅低速分别验证侧别和正向抬升，恢复横梁姿态后才允许完整双Z调整。观察不清不能靠猜测填写z_positions。
3. 确认真实G28、PA11触发及安全探点。厂商启动路径可能伪造homed_axes，不能把该标志当作实际归零证据。
4. 按所选功能验证风扇独立通道、网格可达范围和计划。自适应床网PLAN_ONLY可验证算法范围，不代替机械可达性。
5. 有ADXL时核对定制Linux MCU协议，再做高位无接触检查、受控接触重复性、接触窗口和首层。没有支架时不执行硅胶条接触路径。不得把降低阈值、扩大窗口或降低Z下限当成通用消错方法。
6. 运行自己适配的完整切片开始流程和首层测试，记录功能、参数、版本和结果；保留尚未验收项。冷拔、提示音、材料配方作为独立可选维护功能验证。

长耗时G-code请求返回nginx504时，后端可能仍执行。先查询当前状态/命令进度，不自动重发归零、加热、挤出或接触命令。

## 出错时

- UART报错：回到供电、模块/跳线、引脚和地址核对，不先改变机械坐标。
- Z_TILT越调越歪：停止，检查实际侧别、z_positions顺序与方向，不通过放宽容差掩盖。
- ADXL无触发/高位误触发：停止接触流程，检查对应raw轴、传感器、LinuxMCU命令、配方和机械响应。通信/恢复错误禁止盲目重复下探。
- 首层偏差：检查PA11基准、测量点床网补偿、已存在offset和自己的材料首层修正，不能照抄+0.140。
- `RESPOND`格式错误：旧扩展命令解析器会在引号内的分号截断，提示文字用and等替代`;`。仓库冷拔宏已采用修复文本。
- 网页层数异常：检查文件元数据、实际UI算法与变层高/Z-hop，不能默认需要升级整个Klipper。

## 回退

先确认机器空闲并知道哪些文件已改。恢复配套的原Linux MCU程序、对应主机模块和配置，按实际服务关系重新启动；恢复之前比较当前文件是否已被用户后续修改，避免覆盖新设置。保留证据和失败日志的脱敏副本。

运行 `python -B -m unittest discover -s tests -v` 在开发电脑上做离线检查，不连接打印机。Python3的回归通过不证明Python2部署成功，应以目标解释器再做不执行硬件动作的兼容检查。
